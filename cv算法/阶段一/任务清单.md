# OpenCV 传统视觉缺陷检测项目——实践指南

> **项目定位**：计算机视觉入门实战｜工业表面缺陷提取｜不使用深度学习
>
> **建议用时**：基础版 3～5 小时；完成对比、误差分析与报告约 1～2 天
>
> **最终目标**：在一张钢板表面图像中自动找出候选黑斑缺陷，输出数量、像素面积、位置、尺寸和可视化标注；在 10 张图像上测试并解释算法的适用范围。

## 1. 项目背景与目标

### 1.1 数据集

- 推荐数据集：**NEU Surface Defect Database（NEU-DET）**
- 下载页面：https://www.kaggle.com/datasets/kaustubhdikshit/neu-surface-defect-database
- **基础阶段只使用 `patches`（斑块）类别中 10 张图片**，优先挑选缺陷明显的图片。目录名称可能随下载来源不同而变化，请按实际目录定位。
- 数据多为灰度图：仍需理解灰度化代码；读入时可采用彩色读入后转灰度，或直接以灰度方式读入，说明两种方式的区别。
- **暂不使用 YOLO、U-Net 等神经网络，也不需要训练模型。**

### 1.2 整体流程

```text
输入钢板图片
   ↓
图像读取 / 灰度化
   ↓
滤波降噪（均值 / 高斯 / 中值对比）
   ↓
阈值分割（固定阈值 / Otsu 对比）
   ↓
形态学处理（开运算 / 闭运算）
   ↓
连通域统计 + 面积过滤
   ↓
缺陷框标注 + 结构化结果导出
   ↓
多图测试 + 失败案例分析
```

## 2. 项目文件结构与交付物

建议使用下面的结构（最终以此作为验收依据）：

```text
opencv-defect-detection/
├── data/
│   └── images/                   # 10 张原始测试图（不修改源文件）
├── src/
│   └── defect_detection.py       # 主程序，按步骤拆分函数
├── outputs/
│   ├── steps/                    # 过程图：每张图各步骤结果
│   ├── results/                  # 最终带缺陷框的图片
│   ├── defects.csv               # 每个检测到的缺陷占一行
│   └── summary.csv               # 每张图的缺陷总数、总面积等
├── reports/
│   ├── filter_comparison.png     # 3 种滤波结果对比
│   ├── threshold_comparison.png  # 2 种阈值结果对比
│   └── experiment_report.md      # 实验方法、效果与失败案例
├── requirements.txt
└── README.md                     # 运行说明
```

### 2.1 最终需要交付的内容

1. **可运行程序**：`src/defect_detection.py`，输入一张图或图片文件夹，输出检测结果。
2. **过程图**：灰度图、滤波图、阈值二值图、形态学结果图、连通域标注图。
3. **结果图**：每张输入图都有一张已画框的检测结果图。
4. **结构化数据**：`defects.csv` 和 `summary.csv`。
5. **对比图**：不同滤波方法、不同阈值方法的对比结果。
6. **实验报告**：讲清每一步为什么做、参数为什么这样选、成功与失败案例。
7. **运行文档**：环境、依赖、数据位置、运行命令、输出路径。

> **重要说明**：这里的“面积”是候选缺陷的**像素面积（px²）**，不是外接框面积，也不是现实物理面积（mm²）。没有相机标定或像素尺寸信息时，不要把 px² 换算成 mm²。


**环境验收**：能够导入 `cv2`、`numpy`、`matplotlib`；能够读取至少 1 张测试图，并打印 `shape` 和 `dtype`。

## 4. 分阶段任务与验收标准

### 阶段 A：读取与灰度化

**需要完成**
- 使用 `cv2.imread()` 读取图像，检查是否读取成功。
- 输出原图尺寸、通道数、数据类型、灰度最小值 / 最大值。
- 了解 `cv2.cvtColor(..., cv2.COLOR_BGR2GRAY)` 的作用。若数据已经是灰度图，说明为何不需要重复转换。

**需要输出**
- `outputs/steps/sample_01_01_gray.png`
- 终端记录：`shape`、`dtype`、`min`、`max`。

**验收清单**
- [x] 图片读取成功，找不到文件时有明确提示。
- [x] 能解释 BGR、RGB、Gray 的区别。
- [x] 能说明灰度化为何利于后续单通道阈值处理。

### 阶段 B：滤波比较

**需要完成**
- 对同一张图分别执行均值滤波 `cv2.blur()`、高斯滤波 `cv2.GaussianBlur()`、中值滤波 `cv2.medianBlur()`。
- 初次尝试统一使用 3×3 或 5×5 核（记录具体参数），比较噪声抑制和边缘模糊。
- 选择一种滤波方式供后续流程使用，说明理由。

**需要输出**
- `reports/filter_comparison.png`：原图与 3 种滤波图并排。
- `outputs/steps/sample_01_02_filtered.png`：最终选用的滤波图。

**验收清单**
- [x] 三种滤波方法都能运行并生成图像。
- [x] 能说明均值、高斯、中值滤波的原理差异。
- [x] 能解释为什么过强滤波可能消除细小缺陷。
- [x] 记录滤波核尺寸与选择依据。

### 阶段 C：阈值分割

**需要完成**
- 观察灰度直方图，初步判断缺陷比背景亮还是暗。
- 对黑斑先尝试**反向二值化**（`cv2.THRESH_BINARY_INV`），使候选缺陷为白色、背景为黑色。
- 分别试固定阈值与 Otsu 自适应选择全局阈值（`cv2.THRESH_OTSU`）。
- 对比结果：有无背景误检、缺陷断裂、漏检。

**需要输出**
- `reports/threshold_comparison.png`
- `outputs/steps/sample_01_03_binary.png`
- 在报告中记录固定阈值数值与 Otsu 算出的阈值。

**验收清单**
- [ ] 二值图中候选缺陷主要显示为白色，背景为黑色。
- [ ] 能说明 `THRESH_BINARY` 与 `THRESH_BINARY_INV` 的区别。
- [ ] 能比较固定阈值和 Otsu 的优缺点。
- [ ] 能指出至少 1 个因光照或纹理导致的潜在误检。

### 阶段 D：形态学后处理

**需要完成**
- 使用 `cv2.getStructuringElement()` 构造结构元素。
- 分别测试开运算（抑制小的白色噪点）和闭运算（填补小孔 / 连接近邻断裂区域）。
- 对比不同核尺寸（如 3×3、5×5）的效果，避免过度连接不同缺陷。

**需要输出**
- `outputs/steps/sample_01_04_morphology.png`
- 报告中附上形态学操作前后对比图和核大小。

**验收清单**
- [ ] 可以独立调用 `cv2.morphologyEx()`。
- [ ] 能解释开运算与闭运算的顺序及适用场景。
- [ ] 能举出一个“形态学处理过强导致结果变差”的例子。

### 阶段 E：连通域与缺陷统计

**需要完成**
- 使用 `cv2.connectedComponentsWithStats()` 提取各连通域。
- **跳过背景标签 0**，对候选区域逐一提取统计值。
- 根据最小像素面积 `min_area` 过滤很小的噪点；这个阈值需通过测试决定，不能当作普适常量。
- 对每个候选缺陷输出：图像名、ID、`x`、`y`、`width`、`height`、`area_px`、中心点 `(center_x, center_y)`。
- 区分：`area_px` 是白色像素数；`width * height` 是外接矩形面积。

**需要输出**
- `outputs/defects.csv`：每个候选缺陷 1 行。
- `outputs/summary.csv`：每张图 1 行，至少有 `image_name, defect_count, total_area_px`。

**验收清单**
- [ ] 不把背景标签当作缺陷。
- [ ] 所有保留缺陷都有位置、宽高、中心点与像素面积。
- [ ] 没有缺陷时可以正常输出 0 个缺陷，不报错。
- [ ] 能解释为什么需要最小面积过滤以及误删风险。

### 阶段 F：可视化与批量处理

**需要完成**
- 使用 `cv2.rectangle()` 在**原图**上绘制候选缺陷外接框。
- 可选：使用 `cv2.putText()` 添加缺陷 ID 和像素面积。
- 批量处理 10 张图，保存每张图的标注结果。
- 保留输入原图不变，并确保重复运行不会因为缺少输出目录而报错。

**需要输出**
- `outputs/results/sample_01_annotated.png` 等 10 张结果图。
- `outputs/defects.csv` 和 `outputs/summary.csv` 覆盖所有测试图片。

**验收清单**
- [ ] 10 张图都被处理，且每张图都有对应结果文件。
- [ ] 检测框与连通域位置对应，不发生明显坐标偏移。
- [ ] 结果表的缺陷数与图像上有效框的数量一致。
- [ ] 处理失败的图片有清晰日志，不影响其他图片的处理。

### 阶段 G：对比实验与误差分析

**需要完成**
- 固定一组参数处理 10 张图，**不要每张图单独手动调参后再宣称通用**。
- 从中选 2 张较成功的图片、2 张失败或存在问题的图片，记录原因。
- 至少比较：3 种滤波方式、固定阈值 / Otsu、形态学操作前 / 后。
- 将误检、漏检与背景纹理、噪声、光照变化、缺陷形状等因素联系起来。
- 可选进阶：在人工标注了真实缺陷数量 / 区域后，再计算准确率、召回率或 IoU；没有标注不能直接声称这些指标。

**需要输出**
- `reports/experiment_report.md`，包括：方法流程、核心参数表、对比图、成功案例、失败案例、局限性与下一步改进。

**验收清单**
- [ ] 在 10 张图上完成统一参数的测试。
- [ ] 提供至少 2 个成功案例、2 个问题案例。
- [ ] 说清至少 2 个误检 / 漏检原因。
- [ ] 能解释何时传统阈值方法难以应对，需要自适应阈值、背景校正或学习式方法。

**`outputs/defects.csv`：**

```csv

sample_01.jpg,1,35,42,18,24,156,43.5,53.5
```

```csv

sample_01.jpg,2,238
```

位置 `(x, y)` 表示外接框左上角坐标；图像坐标原点在左上角，x 向右、y 向下。`center_x`、`center_y` 记录外接框中心，允许小数。

## 7. 推荐实施顺序（避免一次性写完整系统）

| 顺序 | 当次只做什么 | 完成后如何确认 |
|---|---|---|
| 第 1 次 | 用 1 张图完成读取、灰度与 3 种滤波 | 能看到 4 张可对比的图 |
| 第 2 次 | 在这张图上完成阈值 + 形态学 | 得到可辨认的二值缺陷区域 |
| 第 3 次 | 完成连通域统计与画框 | 可以逐个打印缺陷参数并可视化 |
| 第 4 次 | 处理 10 张图并导出 CSV | 10 张结果图 + 2 份表格 |
| 第 5 次 | 完成参数对比和失败案例分析 | 实验报告能说明为何成功 / 失败 |

## 8. 进阶方向（基础验收通过后再做）

1. **局部阈值 / 背景校正**：针对背景不均匀、全局阈值误检的问题。
2. **形状特征**：加入周长、长宽比、圆度，区分斑块与细长划痕。
3. **精度评估**：少量人工标注缺陷掩膜，计算 IoU、Precision、Recall。
4. **与深度学习对比**：使用相同图片评估 YOLO 或分割模型；目标检测框与分割像素面积不能直接等同。

## 9. 完成定义（Definition of Done）

**基础版完成**：A～F 六阶段全部通过，独立处理 10 张图，得到最终标注图与两份 CSV。

**完整练手项目完成**：基础版完成，并通过 G 阶段；能够解释流程、方法选择、关键参数、至少两个失败案例与改进思路。

> 核心不是让每张图片都检测正确，而是：**自己实现一条可复现、可解释、可输出定量结果的传统视觉检测流水线，并能诊断失败原因。**
